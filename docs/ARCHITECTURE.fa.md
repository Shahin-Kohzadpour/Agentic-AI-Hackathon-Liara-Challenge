**معماری و قرارداد عملیات نگهبان**

**مرزها**

`src/core.ts` مالک جریان عملیات است. `src/store.ts` وضعیت SQLite و قفل پروژه را نگهداری می‌کند. `src/snapshots.ts` manifest و هویت محتوای منبع را ثبت می‌کند. `src/agent.ts` فقط پیشنهاد اصلاح می‌گیرد. `src/candidate.ts` دامنهٔ JavaScript پذیرفته‌شده برای تابع نمونه را محدود می‌کند. `runner/verify.mjs` و fixtureهای مرجع بیرون از منبع قابل‌ویرایش قرار دارند.

`src/liara.ts` تنها واسط API و CLI است. کلید Liara از env سرور می‌آید و به Codex یا محیط اجرای پروژه منتقل نمی‌شود. `src/server.ts` نشست انسانی، SSE و API را ارائه می‌کند. `src/mcp.ts` آداپتر ابزارهاست و تأیید انسانی نمی‌سازد.

**جریان رخداد**

`collecting → patching → testing → awaiting_approval → deploying → verifying → resolved`

شکست هر مرحله به `failed` و رد انتشار به `rejected` می‌رود. برای نمونهٔ زنده، release باید با منبع ثبت‌شده متناظر باشد و خطای زنده نیز با سناریوی بازتولید مطابقت داشته باشد. HTTP 502 همراه با باگ محلی 500، به‌تنهایی مجوز patch کد نیست.

**قرارداد ActionPlan**

- `projectId` و `kind`: مقصد و عمل محدود.
- `snapshotId` و `digest`: منبع ثابت انتشار.
- `baseRevision`، `baseSnapshot` و `baseRelease`: پیش‌شرط اجرای مجوز.
- `status`، `approvedAt`، `executedAt` و `expiresAt`: تصمیم و مصرف مجوز.
- `risk`، `cost` و `summary`: توضیح قابل‌فهم برای کاربر.
- `result` یا `error`: نتیجهٔ واقعی و محدودیت.

ایجاد پیشنهاد، تغییری در سرویس نمی‌دهد. روش ثبت تأیید فقط در مسیر نشست خصوصی مرورگر وجود دارد. method مشترک اجرا دوباره پیش‌شرط‌ها را بررسی می‌کند؛ annotations ابزار یا محدودیت ظاهری UI کافی نیست.

**شکست و بازگشت**

timeout خارجی ممکن است پس از انجام واقعی عمل رخ دهد. در این حالت retry نوشتنی خودکار انجام نمی‌شود و بررسی دستی release لازم است. اگر فرآیند مالک هنگام اجرا متوقف شود، عملیات هنگام راه‌اندازی دوباره نامشخص و شکست‌خورده ثبت می‌شود. helperهای خواندن یا آماده‌سازی، قفل‌های فرآیند فعال را پاک نمی‌کنند.

منبع قبلی همیشه با نسخهٔ سالم برابر نیست؛ نسخهٔ آغاز سناریوی ۵۰۰ عمداً معیوب است. پیش از پیشنهاد بازاستقرار، آزمون مستقل منبع قبلی اجرا می‌شود. بازگشت فقط به منبع گذراندهٔ آزمون و با مجوز تازه ممکن است.

**محدودیت‌ها**

تک‌مالک، تک‌worker، اجرای محلی Linux و برنامهٔ نمونهٔ مشخص. snapshot ثبت‌شده و کلاینت محلی مورد اعتمادند؛ مقابله با مالک مخرب سیستم‌عامل یا ایمن‌سازی کامل اجرای چندمستأجری ادعا نمی‌شود. قیمت از حساب دریافت می‌شود و تضمین قیمت آینده نیست. ثبت درخواست CPU و حافظه به معنی تعیین واحد یا تازگی همهٔ پاسخ‌های ارائه‌دهنده نیست. نبود secret در فیلدهای ساختاریافته، تضمین پاک‌بودن هر متن دلخواه نیست.
