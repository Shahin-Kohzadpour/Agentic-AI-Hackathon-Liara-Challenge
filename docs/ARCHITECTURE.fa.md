# معماری و قرارداد عملیات

نگهبان یک کنترل‌پلین محلی است که عملیات را روی یک برنامهٔ ثبت‌شدهٔ لیارا انجام می‌دهد. این سند مرزها، وضعیت‌ها و قواعدی را توضیح می‌دهد که نباید با تغییر UI یا ابزار نقض شوند.

## مرز ماژول‌ها

| ماژول | مسئولیت | چه چیزی ندارد |
| --- | --- | --- |
| `src/core.ts` | جریان رخداد، جمع‌آوری شواهد، پیشنهاد عملیات، تأیید، انتشار، بررسی نتیجه | دسترسی مستقیم به شبکهٔ لیارا یا مدل |
| `src/store.ts` | SQLite (سندها، رویدادها، قفل پروژه) و تراکنش | منطق عملیات |
| `src/snapshots.ts` | ساخت snapshot، digest و بررسی دست‌نخورده بودن فایل‌ها | اجرا یا انتشار |
| `src/agent.ts` | تنها تماس با Codex؛ خروجی JSON با schema | ابزار، شبکه، کلید لیارا، اختیار انتشار |
| `src/candidate.ts` | اعتبارسنج نحوی و معنایی تابع نمونه | اجرای کد |
| `src/runner.ts` | `bubblewrap`، timeout، سقف خروجی | تصمیم‌گیری |
| `src/liara.ts` | تنها واسط API و CLI لیارا؛ پالایش خروجی | تأیید یا تصمیم |
| `src/server.ts` | نشست انسانی، CSRF، SSE، API محلی، صفحهٔ نمونه | اجرای عملیات |
| `src/live.ts` | مرورگر واقعی، MCP screencast، گام‌های اتاق زنده | کنترل مدل روی مرورگر |
| `src/mcp.ts` | آداپتر شش ابزار | هیچ ابزار تأیید |
| `src/owner.ts` | قفل مالک فضای داده | پاک کردن قفل فرایند زنده |

`runner/verify.mjs` و fixtureهای مرجع بیرون از snapshot قابل‌ویرایش قرار دارند؛ مدل نمی‌تواند آزمون خودش را بنویسد.

## جریان رخداد

```text
collecting → patching → testing → awaiting_approval → deploying → verifying → resolved
     │            │          │              │
     └────────────┴──────────┴──────────────┴──→ failed
                                            └──→ rejected
```

- شکست هر مرحله رخداد را به `failed` می‌برد و علت را ثبت می‌کند.
- رد انتشار به `rejected` می‌رود و سرویس تغییر نمی‌کند.
- برای پروژهٔ زنده، release فعلی باید با منبع ثبت‌شده متناظر باشد؛ HTTP 502 همراه با باگ محلی 500 مجوز patch کد نیست.
- قرارداد پس از انتشار را منبع تأییدشده تعیین می‌کند. اگر همان snapshot در محیط جدا شکست بخورد (بازنشانی عمدی نمونه)، انتشار تا دیده‌شدن پاسخ ۵۰۰ واقعی روی لبه تمام‌شده ثبت نمی‌شود. برای اصلاح، انتظار، قرارداد سالم و دو پاسخ صحیح متوالی روی همان release است.

## قرارداد ActionPlan

- `projectId` و `kind`: مقصد و عمل محدود.
- `snapshotId` و `digest`: منبع ثابت انتشار و اثر انگشت آن.
- `baseRevision`، `baseSnapshot` و `baseRelease`: پیش‌شرط اجرای مجوز.
- `status`، `approvedAt`، `executedAt` و `expiresAt`: تصمیم و مصرف مجوز (۳۰ دقیقه، یک‌بارمصرف).
- `risk`، `cost` و `summary`: توضیح قابل‌فهم برای انسان.
- `result` یا `error`: نتیجهٔ واقعی و محدودیت.

ساخت پیشنهاد تغییری در سرویس نمی‌دهد. مسیر ثبت تأیید فقط در session خصوصی مرورگر وجود دارد. method مشترک اجرا دوباره پیش‌شرط‌ها را بررسی می‌کند؛ annotation ابزار یا محدودیت ظاهری UI کافی نیست.

## اجرای جدا

هر snapshot در `bubblewrap` با این کنترل‌ها اجرا می‌شود: `--unshare-all`، `--die-with-parent`، محیط خالی، `/usr` فقط‌خواندنی، mount فقط‌خواندنی منبع در `/app`، `/tmp` جدا، سقف heap ۹۶ مگابایت، timeout ۱۲ ثانیه و سقف خروجی. اعتبارنامه‌ای در محیط اجرا وجود ندارد.

این یک محدودیت اجرای نمونه است، نه sandbox چندمستأجری با سهمیهٔ کامل سیستم‌عامل.

## اتاق زنده

`src/live.ts` یک Chromium واقعی را با Playwright اجرا می‌کند و تصویر را از CDP screencast (و در صفحهٔ ساکن، نمونه‌برداری دوره‌ای) به‌صورت MJPEG بومی پخش می‌کند؛ گام‌ها و وضعیت از SSE جدا می‌آیند تا مرورگر بیننده برای هر فریم تصویر را از نو رمزگشایی نکند.

مسیر ثابت است: ورود به کنسول، انتخاب تیم، مرور اطلاعات کلی/نسخه‌ها/لاگ‌ها، بازکردن ویترین فروشگاه، درخواست واقعی، انتظار برای اصلاح Codex، و پس از تأیید و انتشار، بررسی دوباره و نمایش نسخهٔ تازه. مدل هیچ کنترلی روی این مرورگر ندارد و اعتبارنامهٔ کنسول فقط در فرایند سرور می‌ماند. مسیر فقط با session خصوصی قابل‌تماشاست؛ ابزار MCP به آن دسترسی ندارد؛ حداکثر یک جلسه و چهار اتصال تصویری.

## شکست و بازگشت

- timeout خارجی ممکن است پس از انجام واقعی عمل رخ دهد؛ retry نوشتنی خودکار انجام نمی‌شود و بررسی دستی release لازم است.
- اگر فرایند مالک هنگام اجرا متوقف شود، عملیات در راه‌اندازی بعدی «نامشخص» و شکست‌خورده ثبت می‌شود.
- helperهای خواندن یا آماده‌سازی، قفل‌های فرایند فعال را پاک نمی‌کنند.
- منبع قبلی همیشه سالم نیست؛ نسخهٔ آغاز سناریوی ۵۰۰ عمداً معیوب است. بازگشت فقط به منبعی پیشنهاد می‌شود که آزمون مستقل را بگذراند و مجوز تازه بگیرد.

## محدودیت‌ها

تک‌مالک، تک‌worker، Linux محلی و برنامهٔ نمونهٔ مشخص. snapshot و کلاینت محلی مورد اعتمادند؛ مقابله با مالک مخرب سیستم‌عامل یا ایمن‌سازی کامل اجرای چندمستأجری ادعا نمی‌شود. قیمت از حساب دریافت می‌شود و تضمین قیمت آینده نیست. ثبت درخواست CPU و حافظه به معنی تعیین واحد و تازگی همهٔ پاسخ‌های ارائه‌دهنده نیست. نبود secret در فیلدهای ساختاریافته، تضمین پاک‌بودن هر متن دلخواه نیست.
