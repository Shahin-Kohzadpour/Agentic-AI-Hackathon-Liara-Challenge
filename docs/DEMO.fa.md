**روایت پیشنهادی دموی پنج‌دقیقه‌ای**

این متن برای توضیح روی اجرای واقعی آماده شده است. پیش از ضبط، وضعیت نمونه و مسیرهای بررسی را آماده کنید. کلید ورود داشبورد، فایل `.env`، رمز حساب، پنل اطلاعات شخصی و مقادیر محرمانه نباید در تصویر باشند. هر ویدئوی تولیدشده توسط تست مرورگر بدون صدا، پیش‌نویس است.

**۰۰:۰۰ تا ۰۰:۳۰ — مسئله**

«این نگهبان است؛ یک همکار برای استقرار و رفع خرابی روی لیارا. مسئله فقط تشخیص یک پیام خطا نیست. کاربر باید بفهمد چه اتفاقی افتاده، چه تغییری پیشنهاد می‌شود و نتیجه واقعاً چه بوده است. در این نمونه، برنامه روی لیارا اجرا می‌شود و کاربر روی عملیات حساس کنترل دارد.»

نمایش: داشبورد، پروژهٔ واقعی و برچسب محیط لیارا. تفاوت اجرای محلی و واقعی را مشخص کنید.

**۰۰:۳۰ تا ۰۱:۱۰ — استقرار و اختیار انسان**

«پروژهٔ نمونه با API و CLI رسمی لیارا منتشر شده است. پلن، هزینه و منبع انتشار پیش از ایجاد برنامه مشخص شدند. برای این نمونه یک برنامه و شبکهٔ مستقل ایجاد کردیم. هر تغییر بعدی نیز یک پیشنهاد مشخص دارد؛ مدل نمی‌تواند با نوشتن یک پرچم، خودش را تأیید کند.»

نمایش: پیشنهاد پالایش‌شدهٔ استقرار اولیه یا رویدادهای واقعی آن. اگر build را کوتاه می‌کنید، برچسب و زمان واقعی را نگه دارید.

**۰۱:۱۰ تا ۰۱:۴۵ — خطای واقعی**

«بررسی سلامت پاسخ موفق می‌دهد؛ اما سفارش بدون تخفیف با خطای ۵۰۰ مواجه می‌شود. پس سبزبودن health یا آماده‌بودن release کافی نیست. این خطای محدود عمداً در برنامهٔ آزمایشی قرار گرفته تا چرخهٔ رفع مشکل را ارزیابی کنیم.»

نمایش: صفحهٔ مشاهدهٔ برنامه، یک درخواست واقعی با HTTP 500 و سپس `/healthz`. ادعا نکنید این خرابی یک کسب‌وکار واقعی است.

**۰۱:۴۵ تا ۰۲:۳۰ — شواهد و تشخیص**

«نگهبان وضعیت، لاگ‌ها، release و منابع قابل‌دسترسی را از لیارا می‌گیرد. شواهد زمان و محدودیت دارند. سپس سورس متناظر بررسی و خطا در محیط جدا بازتولید می‌شود. در این رخداد، لاگ و بازتولید نشان می‌دهند فیلد اختیاری تخفیف در کد مقدار پیش‌فرض ندارد.»

نمایش: لاگ مربوط و رویداد بازتولید. نبود دادهٔ منابع را مصرف صفر معرفی نکنید. خروجی محرمانه را باز نکنید.

**۰۲:۳۰ تا ۰۳:۱۵ — اصلاح و آزمون مستقل**

«Codex اصلاح را واقعاً تولید کرده است. خروجی آن فقط یک تابع محدود است و اختیار انتشار ندارد. اصلاح با آزمون‌های مستقل بررسی می‌شود؛ از جمله نبود فیلد، ورودی نامعتبر و حالت‌هایی که در درخواست اولیه به مدل داده نشده بودند. با همیشه ۲۰۰ برگرداندن یا حذف اعتبارسنجی نمی‌توان از آزمون عبور کرد.»

نمایش: diff و نتیجهٔ آزمون‌های مستقل (۱۱ آزمون در نسخهٔ فعلی؛ ویدئوی ضبط‌شده اجرای تاریخی با ۷ آزمون را نشان می‌دهد). توضیح دهید این نسخه فقط نمونهٔ ثبت‌شدهٔ Node.js را پشتیبانی می‌کند و ادعای رفع همهٔ باگ‌ها ندارد.

**۰۳:۱۵ تا ۰۴:۲۰ — تأیید، انتشار و بررسی نتیجه**

«اکنون مقصد، تغییر، منبع و اثر هزینه مشخص‌اند. تا تأیید من، انتشار متوقف است. سرور مجوز را به همین snapshot و نسخهٔ پایه متصل می‌کند؛ اگر چیزی تغییر کند، مجوز معتبر نیست. پس از تأیید، CLI همان منبع را منتشر می‌کند و نگهبان درخواست اصلی و قرارداد پاسخ را روی برنامهٔ زنده بررسی می‌کند.»

نمایش: کارت تأیید، تصمیم واقعی کاربر، انتظار build و نتیجهٔ HTTP. وقتی صحنهٔ build طولانی است، زمان واقعی را در گزارش حفظ کنید و کوتاه‌سازی را روشن اعلام کنید.

**۰۴:۲۰ تا ۰۵:۰۰ — نتیجه، MCP و محدودیت**

«در گزارش نهایی، علت، تغییر، آزمون، تأیید و release قابل‌بررسی‌اند. همان ابزارها از طریق MCP به ایجنت کدنویسی هم متصل می‌شوند. در آزمون، فراخوانی انتشار از MCP بدون تأیید رد شد. این نسخه پایش شبانه‌روزی، تغییر دلخواه پروژه‌ها یا migration دیتابیس ندارد؛ تمرکز آن یک چرخهٔ کامل و قابل‌اثبات از خطا تا بازیابی است.»

نمایش: درخواست موفق، گزارش بازیابی و دانلود JSON. رابط MCP را فقط اگر زمان کافی است کوتاه نشان دهید. عدد صرفه‌جویی، رتبه یا پایداریِ اندازه‌گیری‌نشده اعلام نکنید.
