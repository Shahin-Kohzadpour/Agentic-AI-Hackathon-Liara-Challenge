# روایت دموی پنج‌دقیقه‌ای

متن پیشنهادی برای توضیح روی اجرای واقعی. پیش از ضبط، وضعیت نمونه و مسیرهای بررسی را آماده کنید. کلید ورود داشبورد، فایل `.env`، رمز حساب، پنل اطلاعات شخصی و مقادیر محرمانه نباید در تصویر باشند. ویدئوی تولیدشده توسط تست مرورگر بدون صدا، پیش‌نویس است.

## ۰۰:۰۰–۰۰:۳۰ — مسئله

«این نگهبان است؛ یک همکار برای استقرار و رفع خرابی روی لیارا. مسئله فقط تشخیص یک پیام خطا نیست. کاربر باید بفهمد چه اتفاقی افتاده، چه تغییری پیشنهاد می‌شود و نتیجه واقعاً چه بوده است. برنامه روی لیارا اجرا می‌شود و کاربر روی عملیات حساس کنترل دارد.»

نمایش: داشبورد، پروژهٔ واقعی و برچسب `LIVE`. تفاوت اجرای محلی و واقعی را مشخص کنید.

## ۰۰:۳۰–۰۱:۱۰ — استقرار و اختیار انسان

«پروژهٔ نمونه با API و CLI رسمی لیارا منتشر شده است. پلن، هزینه و منبع انتشار پیش از ایجاد برنامه مشخص شدند و یک برنامه و شبکهٔ مستقل ساخته شد. هر تغییر بعدی هم یک پیشنهاد مشخص دارد؛ مدل نمی‌تواند با نوشتن یک پرچم، خودش را تأیید کند.»

نمایش: پیشنهاد پالایش‌شدهٔ استقرار اولیه یا رویدادهای واقعی آن. اگر build را کوتاه می‌کنید، برچسب و زمان واقعی را نگه دارید.

## ۰۱:۱۰–۰۱:۴۵ — خطای واقعی

«بررسی سلامت پاسخ موفق می‌دهد؛ اما سفارش بدون تخفیف با خطای ۵۰۰ مواجه می‌شود. پس سبز بودن health یا آماده بودن release کافی نیست. این خطای محدود عمداً در برنامهٔ آزمایشی قرار گرفته تا چرخهٔ رفع مشکل ارزیابی شود.»

نمایش: صفحهٔ «مشاهدهٔ برنامه»، یک درخواست واقعی با HTTP 500 و سپس `/healthz`. ادعا نکنید این خرابی یک کسب‌وکار واقعی است.

## ۰۱:۴۵–۰۲:۳۰ — شواهد و تشخیص

«نگهبان وضعیت، لاگ‌ها، release و منابع قابل‌دسترس را از لیارا می‌گیرد. شواهد زمان و محدودیت دارند. سپس سورس متناظر بررسی و خطا در محیط جدا بازتولید می‌شود. اینجا لاگ و بازتولید نشان می‌دهند فیلد اختیاری تخفیف مقدار پیش‌فرض ندارد.»

نمایش: لاگ مربوط و رویداد بازتولید. نبود دادهٔ منابع را مصرف صفر معرفی نکنید. خروجی محرمانه را باز نکنید.

## ۰۲:۳۰–۰۳:۱۵ — اصلاح و آزمون مستقل

«Codex اصلاح را واقعاً تولید کرده است. خروجی فقط یک تابع محدود است و اختیار انتشار ندارد. اصلاح با آزمون‌های مستقل سنجیده می‌شود؛ از جمله نبود فیلد، ورودی نامعتبر و حالت‌هایی که در درخواست اولیه به مدل داده نشده بودند. با همیشه ۲۰۰ برگرداندن یا حذف اعتبارسنجی نمی‌توان از آزمون عبور کرد.»

نمایش: diff و نتیجهٔ آزمون‌های مستقل (۱۱ آزمون در نسخهٔ فعلی؛ ویدئوی ضبط‌شده اجرای تاریخی با ۷ آزمون را نشان می‌دهد). توضیح دهید این نسخه فقط نمونهٔ ثبت‌شدهٔ Node.js را پشتیبانی می‌کند.

## ۰۳:۱۵–۰۴:۲۰ — تأیید، انتشار و بررسی نتیجه

«اکنون مقصد، تغییر، منبع و اثر هزینه مشخص‌اند. تا تأیید من، انتشار متوقف است. سرور مجوز را به همین snapshot و نسخهٔ پایه متصل می‌کند؛ اگر چیزی عوض شود، مجوز معتبر نیست. بعد از تأیید، CLI همان منبع را منتشر می‌کند و نگهبان درخواست اصلی و قرارداد پاسخ را روی برنامهٔ زنده بررسی می‌کند.»

نمایش: کارت تأیید، تصمیم واقعی کاربر، انتظار build و نتیجهٔ HTTP. وقتی صحنهٔ build طولانی است، زمان واقعی را در گزارش حفظ کنید و کوتاه‌سازی را اعلام کنید.

## ۰۴:۲۰–۰۵:۰۰ — نتیجه، MCP و محدودیت

«در گزارش نهایی، علت، تغییر، آزمون، تأیید و release قابل‌بررسی‌اند. همان ابزارها از طریق MCP به ایجنت کدنویسی هم متصل می‌شوند. در آزمون، فراخوانی انتشار از MCP بدون تأیید رد شد. این نسخه پایش شبانه‌روزی، تغییر دلخواه پروژه‌ها یا migration دیتابیس ندارد؛ تمرکز آن یک چرخهٔ کامل و قابل‌اثبات از خطا تا بازیابی است.»

نمایش: درخواست موفق، گزارش بازیابی و دانلود JSON. رابط MCP را فقط اگر زمان کافی است کوتاه نشان دهید. عدد صرفه‌جویی، رتبه یا پایداریِ اندازه‌گیری‌نشده اعلام نکنید.
